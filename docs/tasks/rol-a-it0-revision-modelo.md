# Revisión de modelo de datos, máquinas de estado y contratos (Iteración 0 — Rol A)

- **Fecha:** 2026-11-15
- **Iteración / compuerta:** Iteración 0 / Compuerta 0
- **Alcance revisado:** `docs/diseno-arquitectonico.md` (caps. 4, 6–11, 18), `docs/vision-alcance.md` (CAR/alcance), propuestas formales de gramática/catálogo de permisos v1 y contratos API v1 (conversación, **pendientes de aprobación en C0**), `docs/diccionario-datos.md`.
- **Regla aplicada:** no se modificaron artefactos congelados; las inconsistencias se registran con referencia a las fuentes y propuesta de corrección/decisión.

## 1. Resumen

Se identificaron diferencias y vacíos principalmente entre: (a) el capítulo 8 del diseño y la propuesta formal de gramática/catálogo de permisos, (b) el modelo de datos v1 (cap. 7) y las máquinas de estado (cap. 9) frente a los contratos API propuestos, y (c) definiciones incompletas de campos/estructuras necesarias para implementación y trazabilidad. Ningún hallazgo se resolvió por suposición; se proponen acciones para reconciliación en Compuerta 0.

## 5. Recomendaciones para Compuerta 0

1. **Reconciliar gramática y catálogo de permisos** (propuesta vs. cap. 8) y congelar una única versión aprobada con matriz preliminar perfil×recurso/acción.
2. **Alinear máquinas de estado y enums del modelo** (especialmente matrícula y usuario) y reflejarlos en contratos de transición.
3. **Completar definiciones de cumplimiento de datos personales** (consentimiento, minimización, acudiente) antes de avanzar a identidad/negocio.
4. **Cerrar convenciones de datos** (`periodo`, `dia_semana`, estados de notificación, semántica de idempotencia en operaciones no-POST).
5. **Establecer fuente de verdad y flujo de OpenAPI** (`docs/contratos` como propuesta, artefacto canónico/generado y CI) sin modificar congelados sin aprobación.
